# Curation Workflow Contract (replanned Feature 003)

This is the **target contract** for the recalibration. Existing CLI commands remain available; newly named options/commands below are planned and must not be presented as already implemented. Curation may call AI and inspect sources. `python -m indo_malay_anki validate`, `build`, and GitHub release never do. Only guarded `export` changes canonical learner TSV and ID ledger.

## Existing command surface to preserve

| Command | Invariant |
|---|---|
| `init --batch ID --topic TOPIC --limit N` | Creates bounded manifest, never duplicates a batch ID. |
| `packet`, `bundle`, `ingest`, `ingest-bundle` | Versioned role-specific packets and schema-checked responses; verifier is blinded to generator rationale. Whole bundle response validates before ingestion. |
| `route --role ROLE` | Reads central provider/model configuration; actual invoked model is recorded separately. |
| `check`, `finalize-hold`, `finalize-reject`, `report` | Deterministic outcome, explicit finalization and reconciled open/closed reports. Under policy v2, `finalize-reject` requires a typed affirmative reason and supporting ref where applicable. |
| `export --batch ID ...` | Closed, accepted-only, cross-batch duplicate screened, recoverable ledger/TSV transaction; idempotent IDs. |

## Role dependencies and decisions

Candidate discovery, normalized duplicate screening, separate locale usage, relation proposal, inspected claim evidence/audit, and **independent verification** remain distinct. The verifier sees neutral candidate/evidence and relation definitions, not generator rationale or preferred approval. Generation cannot approve itself. Prompt packets and historical manifest prompt versions are immutable. Policy version is separate from prompt version.

The `ordinary-fast` path requires clear cue and aligned meaning, no unresolved overlap, two independent inspected claim-relevant signals for key meaning/usage and comparative preference when claimed, no material contradiction, and independent verifier agreement. Adversarial review is marked `skipped-low-risk` with reason. Escalate on false friend, conflicting evidence, verifier disagreement, ambiguous semantics, register/region concern, disputed everyday preference, semantic overlap, rarity, or weak evidence. An escalation packet must be available **because** of conflict/disagreement, even if ordinary preverification blocks acceptance. Escalated ordinary candidates receive targeted review within budget. False friends require evidenced meanings in both locales and misleading contrast plus separate verifier and mandatory adversarial agreement. An adversarial objection must name a concrete defect or material unresolved risk; generic hesitation cannot veto.

`pending` is unfinished processing and prevents closure/export. Final `accepted` passes all risk-path gates; `hold` is plausible but materially unresolved, including missing/unavailable evidence or exhausted budget; `rejected` has affirmative typed grounds. A failed source retrieval is not contradiction. At a budget cap, apply the gate to available evidence: accept if complete, hold unresolved plausibility, reject only documented disproof. A completed stage may be reused only while its packet/input digest, prompt version and upstream inputs match; an unsuccessful later attempt cannot mask an earlier compatible success.

## Evidence and concurrency

Cache only inspected, scoped source observations. Reused observations are linked to current candidate claims, with original provenance, access method, limits and source-group identity, and rechecked for relevance, independence and contradiction. Bare URLs and model flags count as no audited support. Copies/mirrors count once. Dictionary existence does not establish preferred everyday choice.

Freeze matching rules, topic allocations, generation prompt/source-access conditions and a common audit rubric before timed generation. Generate each old/revised ordinary-intent comparison cohort once in its own measured lane through the runner, then freeze both actual candidate ID sets, preliminary matching attributes and response digests before locale research or policy decisions. Keep candidates and elapsed work in their frozen lane after later escalation or false-friend discovery, but exclude their cards from the ordinary numerator. No unrelated candidate work may run inside a lane's active interval; the revised lane stays isolated through canonical promotion. Evaluate elevated-risk examples separately. Record mismatches and shortfalls; do not substitute candidates after seeing outcomes. Historical fixed-candidate replay is separate from end-to-end cohort throughput.

Central versioned config bounds retrieval attempts, verifier calls, adversarial passes, conflict-resolution work, malformed-output retries, provider workers and candidate workers. The provider-neutral runner passes packets as data, invokes local adapter commands without shell interpolation, and records actual call attempts and rate-limit waits; the existing Codex process helper can be one adapter transport. Timed benchmarks must use this runner. Parallelize independent runner calls and source work; keep each candidate's stage order and a single in-flight same-candidate stage. Serialize mutable batch closure, cross-batch duplicate resolution, bundle fan-out reconciliation and export/ID allocation. One model bundle is one provider operation, even if it emits many candidate events. Interrupted fan-out resumes missing candidate/input-digest entries without double counting or canonical data mutation.

## Reporting, promotion and failure

Open reports reconcile `generated = accepted + held + rejected + pending`; closed reports require `pending = 0`. Report historical decisions and canonically promoted cards separately. New reports show risk distribution, missing versus contradictory evidence, stage holds/rejects/escalations, unique defects, retries/budget exhaustion, evidence cache usage, false-negative recovery and stage/active wall-clock work. Count calls by unique instrumented operation ID; manual external invocations have unavailable call timing/usage. Count external retrieval attempts from recorded research operation IDs, not inspected-source rows; mark unrecorded lookup count/latency unavailable. Product wall-clock runs from generation through successful canonical export and includes provider queues, rate limits, backoff, retries, retrieval and applicable pilot handoff/recheck; exclude only logged external pauses between resumptions, reporting those pauses and total calendar span. Log a frozen-rubric evaluation audit performed between provisional export and canonical promotion as an excluded pause with start/end; count resumed correction, handoff, recheck and export work in active time. Keep independent audit time separate from expert active curation time; audit findings cannot silently approve or change a curation decision. Report the count of all newly canonically promoted cards, but compute whole-release cards/hour only when all included batches/reconsiderations have complete active intervals; use one wall-clock window for overlapping work and otherwise label that rate unavailable. For the matched isolated policy comparison, use candidate-frozen old/revised cohorts and a pass/fail/unresolved evidence audit frozen before either timed run, apply the same rubric to every isolated comparator/pilot export and expert output, and count only audit-passing provisional exports. Each audit stores a digest of the evaluated cue/sense, both answers, relation, applicable contrast and supporting claims/evidence. The T076 intermediate target applies only to this like-for-like isolated comparison. For quality-adjusted canonical pilot throughput, count only newly promoted pilot cards with a passing audit matching their final content/evidence digest; re-audit a materially changed card under the same rubric or exclude it from that numerator. Use the pilot cohort's generation-to-canonical-export interval including handoff/recheck. Compute the canonical AI/expert ratio only from the frozen ordinary-intent lane: its audit-passing ordinary-fast canonical promotions divided by its dedicated active interval through canonical promotion, compared with the ordinary expert rate. Keep later-escalated and discovered false-friend candidates and their work in that lane's interval, exclude their cards from the ordinary numerator, and report their outcomes separately. Do not interleave unrelated candidate work; if the lane is empty, positive lane timing cannot be isolated, or the expert rate is zero/unavailable, mark the ratio undefined; a nonempty measured lane with zero ordinary-fast promotions yields a zero ratio against a positive expert rate; do not sum candidate latencies as a substitute for wall clock. Report raw counts, unresolved findings and cohort mismatches separately. Unaudited historical recoveries or other-batch cards may appear in raw release output but never in the quality-adjusted numerator. Reconcile provisional pilot identities to canonical promotions/holds/rejections and check quality guardrails; practical success requires the matched ordinary canonical ratio above 1 at equivalent quality. Do not compare isolated and canonical rates as a like-for-like speedup. The expert audit is evaluation, not a workflow gate.

Malformed AI output and provider/research outages are recorded with raw failure and retry state. Failed or partial runs do not touch canonical learner data. A reconsideration retains original candidate ID and prior decisions, only reruns invalidated stages, and cannot assign a second ID to the same concept. Promotion still screens all accepted candidates together against current TSV, ledger and archives; unresolved overlap blocks export. Export validates prospective TSV/ledger, uses the existing recovery journal and backups, and remains idempotent. No policy, evidence cache, operation ledger or AI call enters normal Anki generation.

An isolated pilot's exported rows and temporary ID ledger are provisional measurement artifacts only. Transfer its validated candidate/evidence/operation/audit history through a digest-checked manifest with an atomic batch-directory import. A conflicting or incomplete bundle is rejected before import. Preserve the pilot decision; after recomputing acceptance and cross-batch overlap against current canonical state, append a versioned revision linked to that decision for any changed outcome, with reason and report version. Only the existing guarded export allocates canonical permanent IDs. Retain origin workspace, file digests, import outcome and composite candidate identity so every pilot export can be reconciled to canonical learner data without repeating valid research.
